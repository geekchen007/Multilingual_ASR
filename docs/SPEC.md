# 多语言 ASR 测评平台规格 v1.0

日期为 2026-11-06。用户要求先完成规格，再以 Python 开发。本文确定首版验收边界。

## 1. 目标与角色

面向几十位 Beta 用户和研发人员，让真实音频经过测试、历史回看、分类标注、研发复核，形成可复现的 Case 与回归集。

- Beta 用户查看自己的测试、音频、结果、标注和处理进度，可反复测试。
- 研发查看团队记录，更新 Case 状态、归因、负责人，并导出已确认回归 Case。
- 登录账户通过命令行创建，密码哈希存储。角色由服务器保存，页面切换不会改变权限。

## 2. 产品与交互

桌面浏览器优先，左侧导航包括在线测评、测试历史、Case 库、统计。冷蓝与深蓝配色。

### 在线测评

入口包括上传音视频、电脑麦克风录音、B 站 / YouTube 链接。录音依赖 localhost 或 HTTPS，先停止录音再提交。链接须保存来源 URL 与选段起止时间，首版以用户补传有权使用的同源文件完成音频测试。无源文件时显示“待补充音频”，保存到历史，提供补传入口。首版不自动下载第三方视频，也不把字幕当作 ASR 输出。只接受 B 站和 YouTube 的 HTTP(S) 主机白名单链接。

音频上传限制 100 MB。使用 FFmpeg 解码验证，统一裁剪为单声道 16 kHz WAV，单个选段最长 120 秒。时间为相对原文件的秒数，默认从 0 开始，留空结束时间时取最多 120 秒。结果详情始终播放实际送测的裁剪片段，保留原文件偏移。

选择语言、场景和 1—3 个模型。提交后自动持久化任务并异步运行，各模型独立成功或失败。某一家失败时保留其他模型的输出。模型显示名称、模型 ID、适配参数快照与演示标记。盲测时隐藏模型身份，投票后揭晓；投票前后切换显示也需经过服务端权限判断。投票可选 A/B/C、都准确、都有问题、跳过，同一用户每轮只保留一票。

模型接入首版支持演示适配器和 OpenAI-compatible multipart /audio/transcriptions 适配器。演示输出明确标识为固定示例，不代表实际识别或竞品水平。真实服务 URL、模型、Key 环境变量名配置在服务器 config/providers.json。不同供应商的专有流式协议属于后续适配范围。

### 测试历史

所有测试均保存，含失败和待补传任务。列表按关键字、语种、执行状态筛选，展示时间、来源、语种、模式、标注数。详情支持播放、标注、投票和重测。重测生成新记录并关联父测试，原始输出不可修改。历史保留音频哈希、原文件时间范围、模型参数快照和耗时。账号隔离覆盖详情、列表、音频下载、标注与重测。

### 分类标注和 Case

一次测试可产生多个标注。每个标注立即成为一个待复核 Case，包含测试 ID、可选模型结果 ID、片段起止位置、选中文字、修正文、问题类型、语言特征、声音条件、场景、影响程度、说明。问题类型必填，其余可选，范围不得超过实际片段。分类列表由服务器返回并校验。

问题类型包括错字、漏识别、多识别、语种错误、数字时间、人名地名、标点格式、断句、出字慢、其他。语言特征包括单语、混说、方言、口音、未知。声音条件包括安静、噪声、背景音乐、远场、多人重叠、未知。影响程度包括影响阅读、改变原意、任务失败、未知。

研发可补充归因、负责人、确认后的参考文本和回归标记，保留原始用户反馈。状态流转为待复核、已确认、处理中、待验证、已解决、重复、无效。状态与字段更新产生审计事件。并发更新采用 revision 乐观锁，冲突返回 409。重复问题记录关联主 Case ID，不删除原始反馈。回归标记要求已确认或后续有效状态、非空参考文本和真实模型输出。演示 Case 可用于演示流程，但不进入正式统计与回归导出。

### 统计

按权限统计测试数、真实测试数、待复核 Case、回归 Case，按语言和类型聚合。Beta 查看个人范围，研发查看团队范围。演示运行单列。首版展示原始投票和问题计数，不对少量 Beta 样本生成泛化排名。WER/CER、流式延迟指标和终端产品比较属于后续版本。

## 3. 技术架构与数据

Python 3.12、Flask、SQLite WAL、本地音频目录、原生 HTML/CSS/JavaScript，单进程服务配线程池执行后台识别。前端定时读取任务详情。SQLite 以短事务保存状态。升级多实例时使用 PostgreSQL、共享对象存储与独立任务 Worker。

实体关系为 User → Test → Result，Test → Case → CaseEvent，Test → Vote。Test 保存用户、素材、哈希、语言、场景、起止时间、父测试、执行状态；Result 保存供应商配置快照和逐家执行结果；Case 保存用户反馈及研发复核字段。音频采用随机文件名，受登录权限保护。Key 只在后端环境变量读取，绝不返回客户端。

启动时把上次残留 running/queued 结果标记为中断，保留已完成结果，用户通过重测恢复。队列限制同时未完成任务数为 40，超过返回可重试错误。外部服务请求有超时，不泄露认证头及供应商原始错误响应。所有写请求进行 CSRF 校验。数据目录、会话密钥由服务本地创建并持久化。

## 4. 接口

| 接口 | 用途 |
| --- | --- |
| POST /login, POST /logout | 登录与退出 |
| GET /api/config | 分类与模型能力 |
| GET/POST /api/tests | 历史筛选 / 新测试 |
| GET /api/tests/{id} | 测试详情 |
| POST /api/tests/{id}/audio | 为待补传任务补音频 |
| POST /api/tests/{id}/rerun | 创建关联重测 |
| GET /api/tests/{id}/audio | 有权限的片段播放 |
| POST /api/tests/{id}/vote | 保存投票并揭晓 |
| POST /api/tests/{id}/cases | 提交分类标注 |
| GET /api/cases | Case 筛选 |
| PATCH /api/cases/{id} | 研发复核与审计 |
| GET /api/regression | 研发导出正式回归 JSON |
| GET /api/stats | 权限范围统计 |

## 5. 验收

1. Beta 登录后上传合法音频并选两个模型，结果自动进入历史；登出再登录仍可查看。
2. 电脑录音可试听并提交，同一音频实际送入所有选中适配器。
3. 无文件的视频链接显示待补传，补音频后可完成测试，时间裁剪与播放一致。
4. 盲测接口投票前不泄露模型名称和固定身份，投票后显示真实模型；原始输出保持不变。
5. 标注包含至少一个分类，Case 入库，可筛选和修改状态，修改有审计；重复 Case 可关联。
6. 重测保留父子关系。单家服务失败、重启中断、无效音频、越权访问、CSRF、并发更新均有可观察处理。
7. 研发导出经过确认的真实回归 Case，包含参考文、音频下载地址与来源信息；Beta 无导出权限。

## 6. 本轮交付与后续

本轮交付可运行源码、启动说明、配置样例、自动化测试与本规格。真实小艺及竞品接口需要用户填入可用地址和密钥后联调。B 站 / YouTube 自动取音频需要后续具备授权的取材服务。服务在本机运行，不自动发布到公网。正式邀请 Beta 时使用 HTTPS 与持久化数据磁盘。
